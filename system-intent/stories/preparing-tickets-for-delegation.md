# Preparing Tickets for Delegation

- Basis: `composite` — an illustrative scene synthesized from the maintainer's stated
  planning practice.

## Scene

Late in a planning session, Salla has grilled the subject into a set of decisions and
`/to-tickets` has proposed tracer-bullet slices with blocking edges. Before the session
ends, each slice must either deserve `ready-for-agent` or say honestly why not. One
slice hides an open question — where a configuration value should live — and threatens
to slip out the door wearing a label it has not earned.

## User stories

1. **As Salla, a context-protecting maintainer, I want the grill's decisions distilled into each ticket's brief so that agents inherit reasoning rather than bare tasks.**

2. **As Salla, I want blocking edges declared between tickets so that the claimable is an honest statement of what can start now.**

3. **As Salla, I want open questions to hold a ticket short of ready-for-agent so that I never delegate ambiguity.**

4. **As Salla, I want an out-of-scope line in each brief so that implementers stop at the edge I chose.**

*The session ends; the tickets sit in the tracker overnight.*

5. **As Salla, I want a ticket I cannot fully specify to land in a state that says it needs me rather than an agent, so that honesty survives the session boundary.**
